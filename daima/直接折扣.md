# 直接折扣促销业务规则说明

本文只描述“促销-新增 / 直接折扣”页面本身的数据创建规则、前置依赖和业务约束。

## 1. 前置要求

统一规范：

1. 每次新增数据前，必须先校验当前页面字段、下拉选项、复选参数和新增功能是否与本文档一致。
2. 存在前置数据缺口时，可以根据对应数据功能的 MD 文档和本次功能规则，先生成指定的数据文件，再通过后台 UI 创建指定数据。

| 前置数据 | 要求 |
| --- | --- |
| 商品档案 | 商品范围的命中商品池必须覆盖全部商品类型，并包含生鲜商品；最少商品数按当前商品类型下拉选项数量计算。具体商品创建规则见 `base-data-specs/商品档案.md`。 |
| 商品类别 | 类别范围需要至少 1 个可选类别；命中类别下的商品池必须覆盖全部商品类型，并包含生鲜商品。 |
| 品牌 | 品牌范围需要至少 1 个可选品牌；命中品牌下的商品池必须覆盖全部商品类型，并包含生鲜商品。 |
| 供应商 | 供应商范围需要至少 1 个可选供应商；作为本次覆盖目标时，命中供应商下的商品池也必须覆盖全部商品类型，并包含生鲜商品。 |
| 会员类别 | 会员等级默认包含 `无`、`所有会员`、`非会员`；其余可选项来自会员类别。选择具体会员类别时，需要该会员类别可用。 |
| 会员档案 | 需要验证会员等级或会员价基础折扣时，需要对应会员。低价优先默认不是会员价与促销价比较，不默认要求会员。 |

## 2. 默认创建规则

1. 有效期默认执行当天。
2. 门店默认总部；启用时段、促销星期、选择门店保持页面默认。
3. 会员等级、促销范围、折扣率、参与促销商品不积分、在会员价基础上折扣未指定时按 seed 随机。
4. 非关键字段保持页面默认或留空，不主动修改。
5. 明细行必须唯一；生成 data-plan 后先校验唯一性，再执行 UI 创建。
6. 低价优先、后单压前单不是默认验证项，只有测试点明确要求时才生成对应多单据数据。

## 3. 字段处理规则

| 字段 | 处理规则 | 关键说明 |
| --- | --- | --- |
| 方案名称 | `自动化-直接折扣-范围-短seed` | 必须唯一，便于查询。 |
| 方案摘要 | 可写入本次测试点或数据说明 | 非必填时可留空。 |
| 起止日期 | 默认执行当天 | 未指定时起止日期都为执行日期。 |
| 启用时段 | 保持页面默认 | 指定时才修改。 |
| 促销星期 | 保持页面默认 | 指定时才修改。 |
| 选择门店 | 保持默认总部 | 指定门店场景才修改。 |
| 会员等级 | 未指定时从 `无`、`所有会员`、`非会员` 和可用会员类别中随机 | 选择具体会员类别时必须准备对应会员；选择 `非会员` 时不录入会员。 |
| 促销范围 | 未指定时从商品、类别、品牌、供应商中随机 | 选择范围后再生成对应明细。 |
| 折扣率 | 未指定时在 `(0, 1]` 范围内随机 | 覆盖测试至少包含最小有效正数、大于 `0` 且小于 `1` 的随机有效值、最大有效值 `1`。 |
| 参与促销商品不积分 | 未指定时随机勾选或不勾选 | 勾选时需要验证积分影响。 |
| 在会员价基础上折扣 | 未指定时随机勾选或不勾选 | 勾选时需要会员和商品会员价数据。 |

## 4. 范围与验证规则

| 促销范围 | 明细要求 | 唯一性要求 | 正反验证 |
| --- | --- | --- | --- |
| 商品 | 明细商品池覆盖全部商品类型，并包含生鲜商品。 | `itemNo` 唯一。 | 明细内商品命中，明细外商品不命中。 |
| 类别 | 至少 1 行类别明细；明细类别命中的商品池覆盖全部商品类型，并包含生鲜商品。 | `categoryNo` 唯一。 | 类别内商品命中，类别外商品不命中。 |
| 品牌 | 至少 1 行品牌明细；明细品牌命中的商品池覆盖全部商品类型，并包含生鲜商品。 | `brandNo` 唯一。 | 品牌内商品命中，品牌外商品不命中。 |
| 供应商 | 至少 1 行供应商明细；作为本次覆盖目标时，明细供应商命中的商品池覆盖全部商品类型，并包含生鲜商品。 | `supplierNo` 唯一。 | 供应商内商品命中，供应商外商品不命中。 |

商品池数量按以下口径计算：

```text
T = 当前商品档案页面“商品类型”下拉选项数量
命中商品池最少促销商品数 = max(T, 测试点指定数量)
生鲜商品 = 命中商品池中的至少 1 个商品，可同时承担某个商品类型覆盖
```

如果某个商品类型在商品档案中需要主商品/成分商品关系，必须按 `base-data-specs/商品档案.md` 同步生成成分商品数据。成分商品是商品档案创建依赖；只有当成分商品本身也被加入当前商品、类别、品牌或供应商范围时，才计入本促销的命中商品池覆盖。

商品参与条件只适用于类别、品牌、供应商范围：

| 模式 | 页面选项 | 默认策略 | 数据要求 |
| --- | --- | --- | --- |
| `none` | 不设置该业务 | 未指定时默认 | 不新增商品条件明细。 |
| `excludeListedGoods` | 以下商品不参与促销 | 指定时设置 | 条件商品必须处于当前范围内；条件商品不命中，同范围未列入商品命中。 |
| `includeListedGoods` | 仅以下商品参与促销 | 指定时设置 | 条件商品必须处于当前范围内；条件商品命中，同范围未列入商品不命中。 |

其他验证规则：

| 验证项 | 触发条件 | 数据要求 | 预期 |
| --- | --- | --- | --- |
| 会员等级 | 会员等级不是“无” | 准备命中会员和无会员或其他等级会员。 | 只有指定会员等级命中。 |
| 会员价基础折扣 | 勾选“在会员价基础上折扣” | 准备会员和商品会员价。 | 有会员价条件时按会员价折扣。 |
| 非会员价基础折扣 | 未勾选“在会员价基础上折扣” | 准备会员价商品。 | 不按会员价基础折扣计算。 |
| 不积分 | 勾选“参与促销商品不积分” | 准备命中和未命中商品。 | 命中商品不积分，未命中商品不受影响。 |
| 低价优先 | 测试点明确要求 | 至少两个可同时命中的促销结果。 | 前端取最低促销价；默认不与会员价比较。 |
| 后单压前单 | 测试点明确要求 | 创建前后两张同类型直接折扣单据。 | 最新同类型促销方案生效，不满足后单条件的数据不被覆盖。 |

低价优先属于前端多促销取价规则，默认不在每个直接折扣场景重复验证。

## 5. 最小覆盖范围

1. 普通直接折扣创建只生成一个促销方案。
2. 商品、类别、品牌范围的命中商品池最少促销商品数为当前商品类型下拉选项数量，并至少包含 1 个生鲜商品。
3. 类别、品牌、供应商范围的范围目标仍可最少 1 个，但该目标命中的商品池必须满足本节商品池数量口径；不能只创建 1 个命中商品。
4. 涉及主商品/成分商品关系时，按商品档案规则额外生成成分商品；成分商品数量不替代促销命中商品池数量。
5. 设置 `includeListedGoods` 或 `excludeListedGoods` 时，同一范围内至少准备命中和反向两类商品。
6. 会员等级为具体会员类别时，至少准备命中会员和无会员或非命中等级会员；会员等级为 `所有会员` 或 `非会员` 时，按该固定选项准备正反数据。
7. 折扣率取值范围为 `(0, 1]`；覆盖测试至少生成最小有效正数、大于 `0` 且小于 `1` 的随机有效值和最大有效值 `1` 三类合法数据。
8. 低价优先或后单压前单场景至少需要 2 张同时可用的直接折扣或相关促销单据。

计算口径：

```text
零售价折扣价 = 零售价 * 折扣率
会员价基础折扣价 = 会员价 * 折扣率
```

是否使用会员价作为折扣基准，由“在会员价基础上折扣”参数和测试点决定。

## 6. 覆盖账本规则

覆盖账本用于验证随机生成结果是否已经覆盖本次要求。普通单次场景只记录本次选择；当任务要求覆盖多个范围、多个参数状态或特殊验证项时，必须记录覆盖缺口并补齐数据。

```json
{
  "promotionScope": {
    "商品": 1,
    "类别": 1,
    "品牌": 1,
    "供应商": 1
  },
  "optionStates": {
    "memberLevel": ["无", "所有会员", "非会员", "指定会员类别"],
    "discountRate": ["minPositiveByPrecision", "randomValidValueInOpenInterval", 1],
    "noPointsForPromotionGoods": [true, false],
    "discountOnMemberPrice": [true, false]
  },
  "productPool": {
    "allItemTypesCovered": true,
    "freshItemCovered": true,
    "sourceSpec": "docs/pos-promotion-demo/base-data-specs/商品档案.md"
  },
  "productParticipationCondition": {
    "none": 1,
    "excludeListedGoods": 1,
    "includeListedGoods": 1
  },
  "specialValidation": {
    "lowPricePriority": "explicitOnly",
    "latestSameTypePlanWins": "explicitOnly"
  }
}
```

明细唯一性不通过、条件商品不属于当前范围、或显式验证项缺少正反数据时，不能进入 UI 创建。
