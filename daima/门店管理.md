# 门店管理业务规则说明

本文只描述“门店管理-新增”页面本身的数据生成规则、前置依赖和业务约束。

## 1. 前置要求

统一规范：

1. 每次新增数据前，必须先校验当前页面字段、下拉选项、复选参数和新增功能是否与本文档一致。
2. 存在前置数据缺口时，可以根据对应数据功能的 MD 文档和本次功能规则，通过后台 UI 创建指定数据。

| 前置数据 | 要求 |
| --- | --- |
| 区域 | 非必填时可保持页面默认或留空；指定区域场景必须先保证区域可选择。 |
| 初始参考价格 | 默认使用页面默认的总部门店；指定参考门店场景必须先保证目标门店可选择。 |
| 默认配送机构 | 直营、加盟默认使用页面默认的总部门店；配送中心没有该参数。指定配送机构场景必须先保证目标机构可选择。 |
| 行政区划 | 门店地址为必填时，省、市、区县必须选择页面可用值；未指定时从可用地址选项中生成合法组合。 |

## 2. 默认创建规则

1. 除特定场景明确要求创建特定门店数据外，门店管理默认按本文规则自动生成。
2. 如果页面能力与本文档不一致，必须记录差异；影响数据保存或覆盖完整性的差异不能静默忽略。
3. 生成数据时，应以最小数据量覆盖全部要求的条件、参数和选项。
4. 具体覆盖维度和最小数据量在字段规则确认后再计算。
5. 默认创建时，非关键字段保持页面默认值，不主动改动。
6. 门店类型、配送价格和同步设置属于默认必须覆盖字段，不能因为未指定参数而跳过覆盖。
7. 每次新增门店必须保证编码、名称唯一。
8. 创建加盟店时，配送价格只能选择 `配送价` 或 `配送价（1+加价率）`，同步设置只包含 `允许总部调价` 和 `门店独立移动支付`。
9. 创建配送中心类型门店时，没有 `默认配送机构` 参数；其余必填字段仍需按页面要求填写。
10. 若页面对不同门店类型有额外字段或禁用字段，以页面实际可保存规则为准，并记录页面差异。

## 3. 字段处理规则

| 字段 | 处理规则 | 关键说明 |
| --- | --- | --- |
| 编码 | seed 派生唯一数字 | 必填，不能与已有门店重复。 |
| 名称 | `自动门店-短标识` | 必填，不超过页面长度限制。 |
| 营业面积 | 生成 `20.00` 到 `5000.00` 的正数 | 必填。 |
| 门店地址 | 生成合法省、市、区县和详细地址 | 必填。 |
| 门店类型 | 按覆盖账本选择 | 必须覆盖 `直营`、`加盟`、`配送中心`。 |
| 配送价格 | 按门店类型过滤后覆盖 | 必须覆盖全部可用配送价格；加盟店仅可选 `配送价`、`配送价（1+加价率）`。 |
| 同步设置 | 按门店类型可见参数覆盖选中和未选中 | 加盟店仅包含 `允许总部调价`、`门店独立移动支付`。 |
| 默认配送机构 | 直营、加盟保持 `[8888] 总部` | 配送中心没有该参数。 |
| 区域 | 保持页面默认或留空 | 指定区域场景才选择。 |
| 初始参考价格 | 保持 `[8888] 总部` | 指定参考价格场景才变更。 |
| 状态 | 保持页面默认正常 | 非状态测试不主动修改。 |
| 联系人 | 留空 | 指定场景才填写。 |
| 联系电话 | 留空 | 指定时使用合法手机号或固话格式。 |

## 4. 门店类型差异规则

| 门店类型 | 配送价格可选项 | 同步设置参数 | 默认配送机构 |
| --- | --- | --- | --- |
| 直营 | `进价`、`配送价`、`零售价`、`成本价`、`进价（1+加价率）`、`配送价（1+加价率）` | `允许总部调价`、`门店独立移动支付`、`允许使用总部供应商`、`允许使用总部批发客户` | 有 |
| 加盟 | `配送价`、`配送价（1+加价率）` | `允许总部调价`、`门店独立移动支付` | 有 |
| 配送中心 | `进价`、`配送价`、`零售价`、`成本价`、`进价（1+加价率）`、`配送价（1+加价率）` | `允许总部调价`、`门店独立移动支付`、`允许使用总部供应商`、`允许使用总部批发客户` | 无 |

生成数据时必须先确定门店类型，再根据门店类型过滤配送价格、同步设置和默认配送机构字段。不能先随机字段后再强行保存无效组合。

## 5. 最小覆盖范围

1. 生成数据前先读取页面当前字段、下拉选项和复选参数。
2. 先确定门店类型，再过滤配送价格、同步设置和默认配送机构。
3. 未指定取值时，优先选择覆盖账本中未覆盖或覆盖次数最少的选项。
4. 以选项最多的覆盖维度作为最小数据量基础；本页面当前最小覆盖数据量为 6 条门店。
5. 生成后对照覆盖账本检查缺口，缺什么补什么。

门店管理当前覆盖维度为：

| 覆盖维度 | 选项数量 | 最小覆盖影响 |
| --- | ---: | --- |
| 门店类型 | 3 | 可并入 6 条配送价格覆盖数据中轮换覆盖。 |
| 配送价格 | 6 | 当前决定最小数据量，至少 6 条门店；加盟店只能覆盖其中 2 个配送价格。 |
| 同步设置 | 每项 2 种状态 | 可并入 6 条门店数据中覆盖选中和未选中；加盟店只覆盖其中 2 个参数。 |

因此，默认最小覆盖数据量为 6 条门店，而不是 `3 + 6 + 2` 条。

同步设置的“全选”“全不选”只针对当前门店类型可见的参数。

| 序号 | 门店类型 | 配送价格 | 同步设置组合 | 默认配送机构 |
| ---: | --- | --- | --- | --- |
| 1 | 直营 | 进价 | 全选 | `[8888] 总部` |
| 2 | 加盟 | 配送价 | 加盟全不选 | `[8888] 总部` |
| 3 | 配送中心 | 零售价 | 全不选 | 不适用 |
| 4 | 直营 | 成本价 | 随机混合 | `[8888] 总部` |
| 5 | 加盟 | 配送价（1+加价率） | 加盟全选 | `[8888] 总部` |
| 6 | 配送中心 | 进价（1+加价率） | 随机混合 | 不适用 |

## 6. 覆盖账本规则

覆盖账本用于验证随机生成结果是否已经覆盖全部要求。门店管理至少记录以下维度，并且必须记录字段适用的门店类型：

```json
{
  "storeType": {
    "直营": 1,
    "加盟": 1,
    "配送中心": 1
  },
  "deliveryPriceType": {
    "进价": 1,
    "配送价": 1,
    "零售价": 1,
    "成本价": 1,
    "进价（1+加价率）": 1,
    "配送价（1+加价率）": 1
  },
  "deliveryPriceTypeApplicableStoreTypes": {
    "进价": ["直营", "配送中心"],
    "配送价": ["直营", "加盟", "配送中心"],
    "零售价": ["直营", "配送中心"],
    "成本价": ["直营", "配送中心"],
    "进价（1+加价率）": ["直营", "配送中心"],
    "配送价（1+加价率）": ["直营", "加盟", "配送中心"]
  },
  "syncSettings": {
    "允许总部调价": {
      "checked": 1,
      "unchecked": 1,
      "applicableStoreTypes": ["直营", "加盟", "配送中心"]
    },
    "门店独立移动支付": {
      "checked": 1,
      "unchecked": 1,
      "applicableStoreTypes": ["直营", "加盟", "配送中心"]
    },
    "允许使用总部供应商": {
      "checked": 1,
      "unchecked": 1,
      "applicableStoreTypes": ["直营", "配送中心"]
    },
    "允许使用总部批发客户": {
      "checked": 1,
      "unchecked": 1,
      "applicableStoreTypes": ["直营", "配送中心"]
    }
  },
  "fieldAvailability": {
    "deliveryOrganization": {
      "availableStoreTypes": ["直营", "加盟"],
      "unavailableStoreTypes": ["配送中心"]
    }
  }
}
```

当一轮数据不足以覆盖全部门店类型、配送价格或同步设置状态时，必须继续生成补齐数据，直到覆盖账本满足要求。对当前门店类型不可见或不可用的字段，不计入该门店类型的缺失覆盖。

## 7. 快照字段

```json
{
  "entity": "store",
  "storeNo": "860603001",
  "storeName": "自动门店-A01",
  "region": "",
  "referenceStore": {
    "storeNo": "8888",
    "storeName": "总部"
  },
  "status": "正常",
  "storeType": "直营",
  "deliveryPriceType": "进价",
  "deliveryOrganization": {
    "storeNo": "8888",
    "storeName": "总部"
  },
  "businessArea": 128.50,
  "storeAddress": {
    "province": "广东省",
    "city": "深圳市",
    "district": "南山区",
    "detail": "自动化测试路1号"
  },
  "syncSettings": {
    "allowHeadOfficePriceAdjustment": true,
    "independentMobilePayment": true,
    "allowHeadOfficeSupplier": true,
    "allowHeadOfficeWholesaleCustomer": true
  },
  "coverageTags": [
    "storeType:直营",
    "deliveryPriceType:进价",
    "syncSettings:allChecked"
  ]
}
```

快照字段只定义创建后需要保存的真实数据字段。具体运行时的快照文件应记录页面实际保存和回显的结果。

如果门店类型为配送中心，快照中不应写入 `deliveryOrganization`。如果门店类型为加盟，快照中的 `syncSettings` 只应包含 `allowHeadOfficePriceAdjustment` 和 `independentMobilePayment`。

## 8. 机器可读契约

```yaml
schema: ui-rule-spec/v1
entity: store
page: 门店管理-新增
uiFlow: zhixuan.store.create
dependsOn: []
optionalDependsOn:
  - region
  - referenceStore
  - deliveryOrganization
criticalFields:
  - storeNo
  - storeName
  - storeType
  - deliveryPriceType
  - businessArea
  - storeAddress
coverageRequired:
  storeType: allOptions
  deliveryPriceType: allOptions
  syncSettings: selectedAndUnselectedForEachOption
conditionalRules:
  storeType:
    加盟:
      deliveryPriceTypeOptions: [配送价, 配送价（1+加价率）]
      syncSettingsOptions:
        - allowHeadOfficePriceAdjustment
        - independentMobilePayment
    配送中心:
      unavailableFields:
        - deliveryOrganization
preGenerationChecks:
  - detectNewRequiredFields
  - detectChangedDropdownOptions
  - detectChangedCheckboxOptions
  - detectNewBusinessControls
generationStrategy:
  dataVolume: minimumRowsForFullCoverage
  defaultMode: coverageLedgerFirst
snapshot:
  - storeNo
  - storeName
  - region
  - referenceStore
  - status
  - storeType
  - deliveryPriceType
  - deliveryOrganization
  - businessArea
  - storeAddress
  - syncSettings
  - coverageTags
```
